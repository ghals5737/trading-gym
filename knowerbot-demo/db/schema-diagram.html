스탯이 화면 어디에 쓰이나

캐시 테이블 없이 매 요청마다 라이브로 계산되는 값들 포함

화면데이터소스
/my → 사전조사 결과 탭 리스크·지식·정보습관 3축 + 설명 investor_profiles 그대로 조회
/my → 스탯 탭 8개 지표 전부, 세션 평균 GET /api/users/me/aggregate-stats — session_stats를 stat_key별 평균(라이브 계산)
/dashboard 나의 투자 체급 판단정확도·공시확인율·리스크관리 3개만 위와 같은 API, 3개만 골라 표시. 세션 없으면 mock 값 폴백
/simulation 이번 시즌 랭킹 수익률 기준 순위 GET /api/rankings/return-rate — 유저별 완료 세션 중 최고 수익률(라이브 계산)
/api/simulation/{id}/stats 세션 하나의 8개 지표 완료된 세션이면 session_stats 조회, 진행 중이면 그 시점까지 데이터로 라이브 계산(저장 안 함)

설계 판단 메모

왜 이렇게 나눴는지 — 나중에 다시 볼 때를 위한 근거

보유 종목(holdings) 테이블을 왜 안 만들었나?

세션의 trades를 종목별로 합산하면 바로 나와요. 이 프로젝트 규모(세션당 매매 수십 건)에서는 매번 재계산해도 충분히 가벼워서, 정합성 깨질 여지가 있는 별도 스냅샷 테이블을 안 만들었어요.

trades에 그날 시가/고가/저가를 왜 같이 저장하나?

KRX 일봉 데이터는 외부 소스라, 나중에 "이게 추격매수였나?" 같은 판단을 하려면 매매 시점의 그날 가격 맥락이 필요해요. 매매 시점에 스냅샷을 남겨두면 외부 데이터를 다시 조인하지 않고 이 행 하나로 습관 판정이 가능해요.

종합(집계) 스탯 테이블을 왜 안 만들었나?

GET /api/users/me/aggregate-stats가 session_stats를 stat_key별로 평균 내는 계산인데, 세션 수가 적어서 매 요청마다 라이브로 계산해도 충분히 가벼워요. 랭킹(/api/rankings/return-rate)도 같은 이유로 캐시 테이블 없이 라이브 계산. 나중에 상황퀴즈·자료 열람 스탯이 추가돼도 이 서비스 안에서 소스만 늘리면 되고, 계산 자체가 비싸지면(예: LLM 호출) 그때 캐시 테이블을 고려하면 됨 — session_stats가 세션 완료 시점에만 영구 저장하고 그 전엔 라이브 계산하는 것도 같은 원칙.

매매 이유(reason_text)는 왜 필수인가?

"안 좋은 투자는 결과가 아니라 과정으로 판단한다"는 원칙 — 그 순간 사용자가 뭐라고 생각했는지가 있어야, 세션 완료 시 AI가 판단 정확도·충동매매·확증편향 같은 지표를 실제 근거를 가지고 채점할 수 있어요. 예전엔 reason_tag(고정 카테고리)도 있었는데, AI가 자유 텍스트를 직접 읽고 판단하는 방식으로 바뀌면서 태그 없이 reason_text만 남았어요.

상황퀴즈·교육콘텐츠(RAG)·XP/캐릭터 테이블은 왜 없어졌나?

스캐폴딩(엔티티+레포지토리)만 있고 실제로 쓰는 서비스·컨트롤러가 하나도 없는 상태로 오래 방치돼 있었어요. 2026-08-14에 사용처 0건인 걸 확인하고 정리 — 같은 날 risk_interventions(프론트 모달은 있지만 응답을 저장하는 백엔드가 없던 것)도 같은 이유로 삭제해서, 지금 남은 10개 테이블은 전부 실사용 중인 것만 남음. RAG는 lib/education-content.ts에 콘텐츠(글 10개)는 이미 써져 있고, 임베딩 파이프라인부터 다시 설계해서 만들 예정 — 그때 education_articles/education_chunks를 다시 만들면서 pgvector 컬럼도 이번엔 제대로 붙일 계획.

사전조사(온보딩)와 모의투자 스탯을 왜 같은 항목으로 안 맞췄나?

측정 대상 자체가 달라요 — 사전조사는 "본인이 스스로 뭘 하겠다고 답한 성향"(선언적, 1회성), session_stats는 "실전에서 실제로 한 행동"(행동적, AI 채점, 누적). 8개 지표를 3개 축에 억지로 매핑하면 안 맞는 게 나와요(예: DIVERSIFICATION·GAMBLING_SIGNAL은 자기보고 설문으로 묻기 애매함). 대신 향후 맞춤 추천 로직에서 완료 세션 0개면 사전조사 기준, 1개 이상이면 모의투자 스탯 기준으로 컷오버하기로 함 — 둘을 블렌딩(평균)하지 않는 이유는, 사전조사가 오래될수록 실제 행동과 어긋날 수 있어서 실전 데이터가 쌓이면 그쪽을 우선하기 위함.

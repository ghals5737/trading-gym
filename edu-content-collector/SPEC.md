# 금융교육 콘텐츠 수집기 (edu-content-collector) 명세서

## 1. 목적

금감원 e-금융교육센터 Open API를 통해 RAG 지식베이스용 교육 콘텐츠의 **메타데이터를 수집하고, 라이선스·형식 조건에 맞는 콘텐츠의 원본 파일을 일괄 다운로드**하는 CLI 프로그램.

이 프로그램의 산출물(메타데이터 카탈로그 + 원본 파일)은 이후 별도 단계인 파싱→청킹→임베딩 파이프라인의 입력이 된다. **파싱·임베딩은 이 프로그램의 범위가 아니다.**

## 2. 대상 API

- 엔드포인트: `https://www.fss.or.kr/edu/openApi/api/eduContents.jsp`
- 인증: 쿼리 파라미터 `authKey` (32자리, 발급받은 키를 환경변수 `FSS_EDU_API_KEY`로 주입. 코드·저장소에 하드코딩 금지)
- 응답 형식: `apiType=json` 사용 (xml도 지원하지만 json 고정)

### 요청 파라미터

| 파라미터 | 값 | 비고 |
|---|---|---|
| apiType | json | 고정 |
| authKey | 환경변수에서 로드 | 필수 |
| makeTypeCode | 제작유형 코드 | 2 도서, 6 카드뉴스, 7 웹진/잡지/신문 (1 영상, 3 웹툰, 5 교구, 8 오디오북은 수집 제외) |
| eduTrgtCntnt | 교육대상 코드 | Y 청년기, U 대학생, A 중장년기 |
| eduCntnt | 교육내용 코드 | 아래 "수집 대상 주제 코드" 참조 |
| fncEngnCode | 운영기관 코드 | 기본은 미지정(전체). 옵션으로 지정 가능 (1 금감원, 13 투자자교육협의회, 33 한국거래소, 15 금융투자협회 등) |
| certYn | 인증구분 | 미지정(전체) |

### 수집 대상 주제 코드 (eduCntnt)

- 2001 예금, 2002 투자의 기초, 2003 투자상품의 활용
- 3001 신용의 이해와 관리, 3002 대출의 기초와 활용, 3004 부채관리
- 4001 위험의 개념과 관리
- 5005 금융사기예방
- 6001 생애재무설계의 개념과 필요성, 6006 노후자금관리

주제 코드 목록은 설정 파일로 분리해 추가/제거가 쉽게 할 것.

### 응답 필드 (활용 대상)

| 필드 | 의미 | 용도 |
|---|---|---|
| contentsSlno | 콘텐츠 일련번호 | 고유 ID, 중복 제거 키 |
| title | 콘텐츠명 | 카탈로그 |
| fncEngnCode | 제작기관 코드 | 메타데이터 (기관명으로 매핑해 저장) |
| makeTypeCode | 제작유형 | 메타데이터 |
| eduTrgtCntnt | 교육대상 | 메타데이터 (난이도 프록시) |
| eduCntnt | 교육내용(주제) | 메타데이터 (RAG 주제 태그) |
| producingYr | 개발년도 | 메타데이터 |
| smrtnCntnt / cntnt | 요약/내용 설명 | 카탈로그 |
| cpyrhtPermCode | 저작물 이용허락 (A~E) | **라이선스 필터** |
| cpyrhtPermCodeEtc | 이용허락 직접입력 | 라이선스가 E일 때 기록 |
| fileDownUrl | 첨부파일 다운로드 URL | 파일 다운로드 |
| xtrnlContentsUrl | 외부 콘텐츠 링크 | 카탈로그에 기록만 (다운로드 안 함) |

## 3. 동작 흐름

```
1. 설정 로드 (주제코드 목록, 대상코드 목록, 제작유형 목록, 출력 경로)
2. 파라미터 조합별로 API 호출 (제작유형 × 교육대상 × 주제코드 조합 루프)
   - 호출 간 지연 1초 이상 (rate limit 배려)
   - 실패 시 3회 재시도 (지수 백오프)
3. 응답 병합 후 contentsSlno 기준 중복 제거
4. 필터링:
   a. 라이선스: cpyrhtPermCode가 A(출처표시 자유이용) 또는 B(출처표시+상업적 이용금지)인 것만 다운로드 대상.
      C/D/E/빈값은 카탈로그에는 기록하되 다운로드하지 않고 status를 구분 기록
   b. fileDownUrl이 비어있으면 다운로드 스킵, status=NO_FILE로 기록
5. 파일 다운로드:
   - 저장 경로: data/raw/{기관명}/{contentsSlno}_{제목슬러그}.{확장자}
   - 확장자는 Content-Disposition 헤더 또는 응답 Content-Type에서 결정
   - 이미 존재하는 파일은 스킵 (멱등성 — 재실행 시 신규분만 받음)
   - 다운로드 실패는 status=DOWNLOAD_FAILED로 기록하고 계속 진행 (전체 중단 금지)
6. 카탈로그 출력: data/catalog.jsonl (콘텐츠당 1줄, 아래 스키마)
7. 실행 요약 출력: 조회 건수 / 필터 통과 / 다운로드 성공·실패·스킵 건수
```

## 4. 카탈로그 스키마 (catalog.jsonl, 1줄 = 1콘텐츠)

```json
{
  "id": "207",
  "title": "...",
  "org_code": "13",
  "org_name": "투자자교육협의회",
  "make_type": "도서",
  "target": "Y",
  "topic_code": "2002",
  "topic_name": "투자의 기초",
  "year": "2023",
  "summary": "...",
  "license": "A",
  "license_etc": "",
  "file_url": "https://...",
  "external_url": "",
  "local_path": "data/raw/투자자교육협의회/207_....pdf",
  "status": "DOWNLOADED",  
  "collected_at": "2026-08-13T14:00:00+09:00"
}
```

status 값: `DOWNLOADED` / `NO_FILE` / `LICENSE_EXCLUDED` / `DOWNLOAD_FAILED` / `SKIPPED_EXISTS`

코드→이름 매핑(기관코드, 주제코드, 대상코드)은 명세 2절의 표 기준으로 상수/설정 파일에 정의할 것.

## 5. 기술 요구사항

- 언어: Python 3.11+
- 의존성 최소화: `requests` 정도만. (표준 라이브러리로 대체 가능하면 그것도 OK)
- 실행: `python collector.py` 단일 명령. 옵션:
  - `--dry-run`: API 조회·필터링·카탈로그 생성까지만, 파일 다운로드 안 함
  - `--org {코드}`: 특정 기관만
  - `--limit N`: 다운로드 상한 (테스트용)
- 로깅: 표준 출력에 진행 상황, `data/collector.log`에 상세 기록
- 설정: `config.yaml` 또는 상단 상수 블록 (주제/대상/유형 코드 목록, 지연 시간, 재시도 횟수)

## 6. 구현 시 확인·검증 사항 (Claude Code가 직접 확인할 것)

1. **페이지네이션 여부**: 공식 문서에 페이지네이션 파라미터가 명시돼 있지 않음. 첫 호출에서 resultCnt와 실제 result 배열 길이를 비교해 잘림 여부를 확인하고, 잘린다면 조합을 더 잘게 쪼개서(주제코드 단위 개별 호출) 우회할 것
2. **응답 JSON 구조**: 예제 응답의 최상위 키가 `reponse`(오타로 보임)로 표기돼 있음. 실제 응답을 확인해 파싱 키를 맞출 것. result가 단건일 때 배열이 아닌 객체로 올 가능성도 방어
3. **resultCode 처리**: resultCode가 성공(1)이 아닐 때 resultMsg를 로그에 남기고 해당 조합은 건너뛸 것 (인증키 오류 시에는 즉시 중단하고 안내)
4. **fileDownUrl 응답 검증**: 다운로드 응답이 HTML(에러 페이지)인 경우가 있을 수 있음. Content-Type 확인 후 HTML이면 실패 처리
5. **파일명 안전화**: 제목의 특수문자·공백을 슬러그 처리, 파일명 길이 100자 제한

## 7. 범위 외 (하지 말 것)

- PDF 텍스트 추출, 청킹, 임베딩 (다음 단계 별도 프로그램)
- 영상/오디오 콘텐츠 다운로드
- e-금융교육센터 웹페이지 크롤링 (API 외 접근 금지)
- 라이선스 C/D/E 콘텐츠의 파일 다운로드

## 8. 완료 기준 (Acceptance Criteria)

- [ ] `--dry-run`으로 전체 조합 조회 시 카탈로그가 생성되고 요약 통계가 출력된다
- [ ] 본 실행 시 라이선스 A/B + fileDownUrl 존재 콘텐츠만 다운로드된다
- [ ] 재실행 시 기존 파일은 스킵되고 신규분만 받는다
- [ ] 개별 다운로드 실패가 전체 실행을 중단시키지 않는다
- [ ] 카탈로그의 모든 항목에 status가 기록되어 "확보 가능/불가 콘텐츠 현황"을 한눈에 파악할 수 있다

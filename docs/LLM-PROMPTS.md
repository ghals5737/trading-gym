# 트레이딩 짐 — LLM 프롬프트 정리

> 2026-08-25 기준. 어댑터 구조(anthropic/openai/gemini/codex-cli 공용)라 프롬프트는 한 곳에만 있고,
> 현재 `AI_PROVIDER=openai`(gpt-4o-mini)로 운영 중.
>
> 설계 전체를 관통하는 원칙 하나: **"AI를 믿지 말고 시켜라."** AI는 말 잘하는 신입사원 같아서,
> 그냥 두면 매번 다른 기준으로 일하고, 말이 많고, 가끔 그럴듯한 거짓말(환각)을 한다.
> 그래서 모든 프롬프트가 ① 채점 기준표를 쥐여주고 ② 참고할 교과서를 펴주고 ③ 답안지 양식을
> 정해주고 ④ 실패했을 때의 비상구(폴백)까지 만들어두는 구조로 돼 있다

---

## 1. 모의고사 스탯 채점 프롬프트

- 위치: `backend/src/main/kotlin/com/tradinggym/backend/service/ai/SessionStatAnalysisPrompt.kt`
- 호출 시점: 모의고사 종료(completeSession) 시 1회 — 결과는 `session_stats`에 영구 저장
- 실측: 채점 소요 3~4초, 메모 문장을 실제로 근거로 인용함

### 프롬프트 원문 

```
너는 '트레이딩 짐'이라는 모의투자 교육 서비스의 AI 코치야. 사용자가 방금 끝낸 모의투자
세션 하나를 턴 순서대로 아래에 줄게(관망한 턴도 포함, 각 매매마다 사용자가 직접 쓴
이유 텍스트도 같이 있어). 이걸 다 읽고 8개 지표를 각각 0~100점으로 채점해줘.
```
→ **메모까지 통째로 주는 이유**: 수학 시험에서 답만 보면 찍었는지 알 수 없다. 풀이 과정을 봐야
실력이 보인다. "삼성전자를 샀다"는 기록만으론 공부하고 산 건지 남 따라 산 건지 모르니,
사용자가 쓴 "왜 샀는지" 메모(=풀이 과정)를 전부 보여준다. 관망 턴까지 주는 이유도 같다 

```
세션 요약: 시작자금 …원, 최종자산 …원 (수익률 …%), 총 …턴, 매매 …건(매수 …/매도 …),
관망 턴 …회, 반대매매 …회, 신용거래 …건, 거래한 종목 수 …개, 매수 중 공시확인 …건.
미수금(신용매수 대출): {상환 기한(발생 후 10턴)을 넘김 — 규칙 위반 | 기한 초과 없음},
세션 종료 시점 미상환 잔액 …원.
미수금 기한 초과나 미상환 잔액이 있으면 RISK_MANAGEMENT_SCORE와 GAMBLING_SIGNAL을
뚜렷하게 감점하고 그 이유에 명시해.
```
→ **요약 숫자를 미리 계산해서 주는이유**: 덧셈은 계산기가 AI보다 정확하다. "공시확인 2/3건"
같은 집계는 서버가 미리 세서 주고, AI에게는 해석만 시킨다.
→ **왜 미수금 감점을 콕 집어 명령하나**: "10턴 안에 못 갚으면 부정적 반영"은 회의에서 정한
서비스 규칙이지 AI가 알아서 판단할 일이 아니다. 규칙은 명령으로 박아둔다.

```
턴별 기록:
[턴 1] 2025-09-12 (TRADED)
  - BUY 삼천당제약 400주 @ 213500원 · 공시확인 안함 · 이유: "리딩방에서 곧 급등한다고 해서…"
…
```
→ 아래 "RAW 데이터" 참고 — DB의 JSON을 이 한 줄 형식으로 바꿔서 넣는다.

```
아래 8개 지표를 각각 판단해서 채점해줘 — 전부 "값이 높을수록 바람직한 투자 습관"
방향으로 통일해서 채점해(예: 위험 신호가 적으면 높은 점수).
판단 정확도(JUDGMENT_ACCURACY), 공시 확인율(DISCLOSURE_CHECK_RATE), 리스크 관리(…),
충동매매 억제(…), 손실회피 성향 억제(…), 확증편향 억제(…), 분산투자(…), 도박성 매매 신호 억제(…)
```
→ **왜 8개 지표를 미리 정해주나**: 선생님한테 그냥 "채점해주세요" 하면 어떤 날은 글씨체를,
어떤 날은 태도를 본다. 채점 기준표(루브릭)를 미리 쥐여줘야 지난달과 이번달 점수를 비교할 수 있다.
→ **왜 3요소(정확성/침착성/공격성)가 아니라 8개를 재나**: 3요소는 **보여주는 단위**이고 8지표는
**재는 단위**다. "정확성 43점"만 받으면 공시를 안 봐서인지 남 말 듣고 사서인지 알 수 없다.
건강검진에서 "건강 나쁨" 한 줄 대신 혈압·혈당·콜레스테롤을 각각 재서 종합 등급을 내는 것과 같다 —
잘게 재야 근거가 남고, 3분류 합산은 수식이라 절대 흔들리지 않는다. 게다가 오늘의 PT(약한 세부
지표를 골라 출제)와 자료실 추천(지표별 RAG 검색어)이 전부 세부 지표 단위로 돌아가서, 3개만 재면
맞춤 문제를 낼 수 없다.

**8개 지표는 무엇이고, 왜 하필 이 8개인가** — 기획안이 잡으려는 나쁜 습관("몰빵매수, 과도한
레버리지, 손절 지연, SNS·리딩방 의존") 하나에 지표 하나씩 대응시키고, 행동경제학에서 검증된
편향 개념 중 **모의고사 데이터(매매 기록+메모)로 실제로 잴 수 있는 것만** 남긴 결과다:

| 지표 | 무엇을 재나 | 무엇으로 재나 | 왜 필요한가 (대응하는 나쁜 습관) |
|---|---|---|---|
| 판단 정확도 | 매매 판단이 상황·근거에 맞았는지 | 메모의 근거 + 이후 가격 흐름 | "일단 사고 보는" 근거 없는 매매 |
| 공시 확인율 | 매수 전 공시를 열어봤는지 | 공시 패널 열람 기록(숫자) | 공시·재무 확인 없이 매수하는 습관 |
| 확증편향 억제 | 보고 싶은 정보만 보는지 | 메모에서 정보 취사선택 패턴 | 리딩방·커뮤니티 말만 믿는 습관 |
| 충동매매 억제 | 근거 없이 급하게 사고파는지 | 메모의 "그냥/급하게/느낌" 표현 + 매매 빈도 | 뇌동매매 |
| 손실회피 대응 | 손실 앞에서 감정적으로 버티는지 | 물타기·손절 지연 행동 + 메모("팔면 손실 확정") | 손절 못 하고 물타는 습관 |
| 도박성 신호 억제 | 잃고 나서 베팅을 키우는지 | 손실 직후 포지션 확대 패턴 | 복구 심리(한 방에 만회) |
| 리스크 관리 | 미수·반대매매 위험을 관리했는지 | 미수 상환 기한 준수·반대매매 횟수(숫자) | 감내 수준 이상의 레버리지 |
| 분산투자 | 한 종목에 몰빵했는지 | 거래 종목 수·집중도(숫자) | 몰빵매수 |

여기서 4개(공시확인·리스크관리·분산·도박성 일부)는 숫자로도 계산되지만, 나머지 4개(판단·충동·
손실회피·확증편향)는 **메모를 읽어야만** 잴 수 있다 — LLM 채점을 쓰는 이유가 바로 이 4개다.

**8개를 3요소로 나눈 기준** — "이 습관이 고장 난 곳이 어디인가"로 나눴다. Pompian(2006)이
투자 편향을 인지적(cognitive) 편향과 감정적(emotional) 편향으로 나눈 분류를 따르고, 거기에
위험행동 축을 자체 추가한 것:

- **정확성 = 머리(인지)의 문제** — 정보를 보고 생각하는 과정이 고장난 것. 몰라서, 확인 안 해서,
  한쪽 정보만 봐서 생기는 실수. 공부와 습관으로 고친다.
  → 판단 정확도(근거가 맞았나), 공시 확인율(정보를 봤나), 확증편향 억제(정보를 골고루 봤나 —
  Pompian 분류에서 확증편향은 대표적 인지 편향)
- **침착성 = 마음(감정)의 문제** — 알면서도 감정 때문에 못 지키는 것. 무서워서, 아까워서,
  분해서 생기는 실수. 지식이 아니라 감정 조절의 문제라 정확성과 따로 잰다.
  → 충동매매 억제(조급함), 손실회피 대응(Pompian 분류에서 손실회피는 대표적 감정 편향 —
  "팔면 손실이 확정되니까"는 계산이 아니라 아까움), 도박성 신호 억제(잃고 나서 만회하려는
  복구 심리 — 겉보기엔 베팅 크기 문제지만 원인이 감정이라 공격성이 아닌 침착성에 둠)
- **공격성 = 스타일(위험행동)** — 위험을 얼마나 크게 잡는가. 옳고 그름이 아니라 성향이라
  좋고 나쁨 색을 안 입힌다. → 리스크 관리·분산투자를 뒤집어서(100-점수) 계산 — 이 둘은
  "안전할수록 높은 점수"라, 뒤집으면 그대로 "위험을 크게 잡는 정도"가 된다.

경계에 있던 지표 하나: **도박성 신호는 공격성 재료로도 볼 수 있지만 침착성에만 넣었다.**
양쪽에 다 넣으면(초안이 그랬다) 같은 지표가 두 축을 동시에 움직여서 "침착성이 오르면 공격성이
자동으로 내려가는" 연동이 생긴다 — 그러면 "침착한데 공격적인 사람"이 구조적으로 나올 수 없어
세 축을 나눈 의미가 사라진다. 지표 하나는 축 하나에만 — 이게 분류의 규칙이다.
→ **왜 방향을 통일하나**: "국어는 높을수록 좋고 수학은 낮을수록 좋음"이면 성적표가 안 읽힌다.
→ **왜 한국어 라벨을 괄호와 같이 주나**: 화면에 보이는 이름 그대로 이해시키고, 출력은 영문 코드로
받아 파싱하기 위해.

```
아래 형식 그대로만, 8줄만 출력해(다른 말 절대 덧붙이지 마):
JUDGMENT_ACCURACY: <0~100 점수> | <한 문장 이유>
…(8줄)
```
→ **왜 형식을 강제하나**: AI는 말이 많다. 그냥 두면 "네, 기꺼이 채점해드릴게요!" 같은 사족을
붙이는데, 이 답은 사람이 아니라 컴퓨터가 자동으로 읽어 점수판에 넣는다. 은행 서류처럼 칸을
정해줘야 기계가 읽는다.
→ **왜 JSON이 아니라 한 줄 형식인가**: JSON은 쉼표 하나만 틀려도 통째로 못 읽는다.
"항목: 점수 | 이유" 한 줄 빈칸 채우기는 형식이 살짝 어긋나도 정규식으로 건져낼 수 있다.
→ **실패하면(8줄을 못 건지면)**: 폴백 채점 — 계산 가능한 4개(공시확인율·분산·반대매매·미수)는
서버가 직접 계산하고, 메모 해석이 필요한 4개는 중립 50점 + "지금은 AI 분석을 만들지 못했어요".
정전이 나도 비상등은 켜지게.

### 이 프롬프트에 첨부되는 RAW 데이터 (실제 캡처)

원천은 `GET /api/sessions/{id}/summary`가 만드는 JSON — 서버가 turn_logs + trades를 턴 단위로
묶은 것. 판정 없이 원본 그대로다 (실제 peer-20-1 테스트 세션에서 캡처, 발췌):

```json
{
  "startingCash": 100000000.0, "finalPortfolioValue": 118480000.0, "returnPct": 18.48,
  "turnCount": 4, "totalTradeCount": 3, "buyCount": 3, "sellCount": 0, "holdTurnCount": 1,
  "forcedLiquidationCount": 0, "creditTradeCount": 1, "uniqueStockCount": 2,
  "disclosureCheckedBuyCount": 0, "debtOverdue": false, "unpaidDebtAtEnd": 16335000.0,
  "turns": [
    { "turnNumber": 1, "turnDate": "2025-09-12", "action": "TRADED",
      "portfolioValue": 100000000.0, "borrowedAmount": 0.0,
      "trades": [ { "side": "BUY", "stockName": "삼천당제약", "quantity": 400, "price": 213500.0,
        "isCredit": false, "viewedDisclosure": false,
        "reasonText": "리딩방에서 삼천당제약 곧 급등한다고 해서 크게 들어갔어요. 마지막 기회라길래요" } ] },
    { "turnNumber": 2, "turnDate": "2025-09-15", "action": "TRADED",
      "trades": [ { "side": "BUY", "stockName": "SK하이닉스", "quantity": 30, "price": 339500.0,
        "reasonText": "그냥 느낌이 좋아서 샀어요" } ] },
    { "turnNumber": 3, "turnDate": "2025-09-16", "action": "TRADED", "borrowedAmount": 16335000.0,
      "trades": [ { "side": "BUY", "stockName": "삼천당제약", "quantity": 100, "price": 207500.0,
        "isCredit": true,
        "reasonText": "삼천당이 떨어졌는데 평단가를 낮추려고 물을 탔어요. 팔면 손실이 확정되니까요" } ] },
    { "turnNumber": 4, "action": "HELD",
      "trades": [ { "side": "HOLD", "reasonText": "더 떨어질까봐 무서워서 아무것도 못 했어요" } ] }

```

이 JSON이 프롬프트 안에서는 이렇게 **한 줄 텍스트로 변환**되어 들어간다
(`toPromptBlock()` — AI가 표를 읽는 것보다 문장을 읽는 게 정확해서):

```
[턴 1] 2025-09-12 (TRADED)
  - BUY 삼천당제약 400주 @ 213500원 · 공시확인 안함 · 이유: "리딩방에서 삼천당제약 곧 급등한다고 해서 크게 들어갔어요. 마지막 기회라길래요"

[턴 2] 2025-09-15 (TRADED)
  - BUY SK하이닉스 30주 @ 339500원 · 공시확인 안함 · 이유: "그냥 느낌이 좋아서 샀어요"

[턴 3] 2025-09-16 (TRADED)
  - BUY 삼천당제약 100주 @ 207500원(신용) · 공시확인 안함 · 이유: "삼천당이 떨어졌는데 평단가를 낮추려고 물을 탔어요. 팔면 손실이 확정되니까요"

[턴 4] 2025-09-17 (HELD)
  - 관망 · 이유: "더 떨어질까봐 무서워서 아무것도 못 했어요"
```

이 데이터에 대한 **실제 LLM 채점 출력** (당시 그대로):

```
JUDGMENT_ACCURACY: 40 | 매매 판단이 다른 사람의 의견에 기반하고 있으며, 명확한 분석이 부족하다.
DISCLOSURE_CHECK_RATE: 0 | 공시 확인이 전혀 이루어지지 않았고, 이는 신뢰성 높은 정보 부족을 의미한다.
IMPULSIVE_TRADING: 30 | 감정에 따라 매매 결정을 내리는 경향이 있어 충동 매매가 의심된다.
LOSS_AVERSION: 50 | 손실 확정 회피를 위해 추가 매수를 하였지만, 전반적으로는 손실 회피가 두드러지지 않았다.
RISK_MANAGEMENT_SCORE: 20 | 미상환 잔액이 존재하며, 신용 거래를 사용했지만 리스크 관리가 부족했다.
…
```

"리딩방" → 판단 정확도 감점, "물타기·손실 확정" 메모 → 손실회피 지적, 미수 미상환 → 리스크 감점 —
RAW의 문장이 그대로 채점 근거로 연결되는 걸 볼 수 있다. 이 8개 점수가 마이페이지에서
정확성(판단+공시+확증편향) / 침착성(충동+손실회피+도박성) / 공격성(리스크관리·분산 역산) 3분류로 합산된다.

## 2. 오늘의 PT 퀴즈 생성 프롬프트 (실전 시나리오형)

- 위치: `backend/src/main/kotlin/com/tradinggym/backend/service/ai/QuizGenerationPrompt.kt`
- 파이프라인: 유저 스탯 중 **가장 약한 지표** 선택 → 지표별 검색어로 RAG(edu_chunks 벡터 검색)
  → 검색 발췌를 근거로 4지선다 1문제 생성 → 출처(기관·자료명·쪽수)를 DB에 고정 저장

### 프롬프트 원문 (지시마다 "왜 이렇게 썼는지" 주석)

```
너는 '트레이딩 짐' 투자 교육 서비스의 AI 코치야. 이 사용자는 "{targetStatLabel}"
지표가 약한 것으로 나타났어.
```
→ **왜 약한 지표 하나를 골라 주나**: 학원 선생님이 숙제를 낼 때 이미 잘하는 단원이 아니라
틀린 단원 문제를 주는 것과 같다. 그래서 사람마다 받는 문제가 다르다.

```
아래 공신력 있는 금융교육 자료를 근거로, 짧은 실전 상황(시나리오)을 하나 주고
"이 상황에서 가장 바람직한 판단"을 고르는 4지선다 퀴즈를 하나 만들어.
- 시나리오는 사회초년생 첫 투자자가 실제로 겪을 법한 상황으로 2~3문장.
```
→ **왜 개념 문답이 아니라 시나리오형인가**: "분산투자란 무엇인가?"(단어 뜻 묻기)는 맞혀도
행동이 바뀐다는 보장이 약하다 — 뜻은 아는데 실전에선 몰빵할 수 있다. "월급 300 사회초년생이
리딩방 추천을 받았다. 어떻게 해야 하나?"처럼 상황을 주고 판단을 시켜야, 진단된 나쁜 습관과
문제가 직접 대응된다(서비스 차별점인 행동 교정과 일치).

```
- 정답 근거는 반드시 참고 자료에 실제로 나온 내용이어야 해(지어내지 마).
```
→ **왜 "지어내지 마"를 명시하나**: AI의 제일 큰 병이 그럴듯한 거짓말(환각)이다. 금융 교육에서
치명적이라, AI 기억에 맡기지 않고 금감원 교과서를 펴놓고 "여기 나온 것만으로 내"라고 시킨다
(오픈북 출제). 시나리오 창작이 들어가는 만큼 이 강제가 더 중요하고, 문제마다 출처 쪽수를
도장 찍어 저장하니 나중에 "어디서 나온 얘기냐"에 답할 수 있다.

```
- 오답 3개는 초보 투자자가 실제로 하는 착각·나쁜 습관에서 뽑아(매력적인 오답).
```
→ **왜 오답 품질까지 지시하나**: 보기가 "①분산투자 ②하늘 ③바다"면 공부 안 해도 맞힌다.
본인이 평소 하던 생각이 오답 보기에 있으면, 틀리는 순간이 곧 배우는 순간이 된다.

```
- 해설에는 왜 정답이 맞는지와 함께, 오답 중 하나가 왜 위험한지도 한 문장 짚어줘.
```
→ **왜 오답 해설까지 시키나**: 이 서비스의 목적이 정답 맞히기가 아니라 나쁜 습관 교정이라,
"당신이 고른 그 선택이 왜 위험한지"까지 말해줘야 학습이 닫힌다.

```
참고 자료: (RAG 발췌 — 아래 RAW 데이터)

아래 형식 그대로, 설명이나 다른 말 없이 정확히 이 형식으로만 출력해:
QUESTION: <문제 한 문장>
OPTION1~4: <보기>
CORRECT: <정답 번호, 1~4 중 하나만>
EXPLANATION: <정답 해설 2~3문장>
```
→ 형식 강제 이유는 채점 프롬프트와 동일(컴퓨터가 읽는 답). **실패 시 폴백은 일부러 없음** —
채점은 "보류"라도 보여주는 게 낫지만, 퀴즈는 엉터리 문제를 그럴듯하게 보여주는 게 최악
(틀린 걸 배워간다)이라 "다시 시도해주세요"로 끝낸다.

### 실제 생성 예시 (약점 지표: 분산투자)

> 사회초년생인 당신은 첫 투자로 100만 원을 주식에 직접 투자하기로 결심했지만, 친구가 추천해준
> 한 종목에만 전액 투자하기로 했습니다. 이 상황에서 가장 바람직한 판단은 무엇일까요?
> ① 모든 자금을 한 종목에 투자한다 ② 여러 종목에 분산투자하여 리스크를 줄인다
> ③ 주식을 사지 않고 예금에 넣는다 ④ 모르는 종목에 직접 투자하기 위해 더 많은 공부를 한다
> — 출처: 예금보험공사 · 대학생을 위한 금융 첫걸음 · 203쪽

"친구 추천 몰빵"이라는 실제 나쁜 습관이 오답 보기에 들어간 상황극이 의도대로 나온다.

## 3. KnowerBot 채팅 프롬프트 (RAG 컨텍스트 주입)

- 위치: `backend/src/main/kotlin/com/tradinggym/backend/service/ai/ChatReplyPrompt.kt`

```
너는 '트레이딩 짐'이라는 모의투자 교육 서비스의 AI 코치 캐릭터 'KnowerBot'이야.
사용자와 채팅으로 자유롭게 대화 중이야. 투자·리스크 관리·이 서비스 사용법 질문이면
최대한 도움이 되게 답하고, 그 외의 잡담이어도 자연스럽게 받아주면 돼.
존댓말로, 친근하지만 전문적인 톤으로, 1~3문장 정도로 짧게 답해.
```
→ **왜 캐릭터·말투·길이를 정해주나**: 정해주지 않으면 어떤 날은 논문처럼 다섯 문단, 어떤 날은
반말이 나온다. 카페 알바생에게 "존댓말로, 친절하게, 짧게"라고 교육하는 것 — 매번 같은
KnowerBot으로 보이게 하기 위해서다. 1~3문장 제한은 채팅 말풍선 UI가 깨지지 않는 길이이기도 하다.

```
참고 자료(공신력 있는 금융교육 자료에서 검색된 발췌 — 답변에 도움이 되면 활용하고
출처(기관·자료명·쪽수)를 자연스럽게 언급해. 질문이랑 안 맞으면 그냥 무시하고 평소처럼 답해):
(RAG 발췌 — 퀴즈와 같은 형식)

지금까지 대화:
사용자: …
KnowerBot: …

사용자: {새 메시지}
KnowerBot 답변만 출력해(다른 말이나 따옴표 절대 덧붙이지 마):
```
→ **왜 답하기 전에 자료를 검색해 끼워주나**: AI 기억에만 맡기면 옛날 정보를 말하거나 지어낸다.
도서관 사서처럼 관련 책을 펴서 옆에 놓아주고 "이거 참고해서 답하고 출처도 말해"라고 시킨다.
→ **왜 "안 맞으면 무시해"라고 여지를 주나**: "오늘 날씨 좋네요" 같은 잡담에 억지로 교과서를
인용하면 이상하다. 애초에 검색 관련도 점수 0.5 미만이면 자료를 아예 안 끼워준다 — 실측 기준으로
관련 있는 질문은 0.68~0.77, 완전 무관하면 그보다 훨씬 낮게 나와서 0.5가 컷라인.
→ **왜 대화 히스토리를 주나**: 앞에서 한 말을 기억 못 하면 대화가 아니다. 최근 대화를 같이 넣는다.
→ 출력 후처리: 모델이 가끔 "KnowerBot:" 접두사나 따옴표를 붙여서, 파서가 관대하게 벗겨내고
400자 초과 폭주 응답은 잘라낸다.

### 이 프롬프트에 첨부되는 RAW 데이터

두 가지가 붙는다:
1. **RAG 발췌** — 퀴즈와 동일한 검색 응답 (위 2번의 RAW와 같은 형식). 실제 예: "분산투자가 왜
   중요한지 알려줘" 질문에 예보 금융 첫걸음 203쪽 발췌가 붙어, 답변 끝에 "📚 참고 자료 · 예금보험공사
   「대학생을 위한 금융 첫걸음」 203쪽"이 자동으로 달렸다.
2. **대화 히스토리** — `chat_messages` 테이블의 최근 대화를 "사용자: …" / "KnowerBot: …" 줄로 변환.

## 4. 온보딩 관련 (참고)

- 답변 적합성 체크·성향 채점·설명문 생성도 어댑터 구조로 LLM 사용(`ConversationAnalysisPrompt.kt`)
  — 6문항 대화 원문(질문+자유 답변 텍스트)을 한 번에 넘겨 문항별 1~4점 + 설명문을 받는다.
  RAW는 `onboarding_conversation_turns` 테이블의 질문·답변 원문.
- 설문 점수 → 정확성/침착성/공격성 **초기 스탯**은 LLM이 아니라 고정 수식
  (`OnboardingService.initialCategoryScores`) — 행동 데이터가 쌓이기 전의 베이스라인이라
  매번 같은 답이 나와야 해서 일부러 AI를 안 쓴다.
